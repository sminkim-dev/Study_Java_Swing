각 문제 파일 안에서 이미지 로딩과 JFrame 생성을 직접 처리합니다. 다른 문제 파일이나 보조 클래스 없이 각각 실행할 수 있습니다.

## 이미지 경로

이미지를 쓰는 1번, 1-(2), 2~5번, 10번은 각 파일의 main() 안에 다음 코드를 직접 적었습니다.

```java
ImageIcon icon = new ImageIcon("<PROJECT_ROOT>/src/image/buddy1.jpeg");
```

- 위 경로의 buddy1.jpeg는 프로젝트에 원래 있던 실제 이미지입니다.
- 교재의 back.jpg, apple.jpg는 없으므로 해당 이름으로 검색하거나 자동 대체하지 않습니다.
- 다른 이미지를 쓰려면 해당 문제의 new ImageIcon(...)에 적힌 경로를 직접 바꾸세요.
- `<PROJECT_ROOT>`는 `Univ_java` 프로젝트 폴더를 뜻하는 대체 문자열입니다. Java가 자동으로 해석하지 않으므로 실행 전에 본인 환경의 실제 절대 경로로 바꾸세요.
- 프로젝트를 다른 컴퓨터로 옮기면 이미지 경로도 그 컴퓨터의 실제 경로로 수정해야 합니다.
- 3·4·5번은 이미지의 원본 크기를 사용합니다.

## 구현 이유

- Swing 화면 생성은 이벤트 처리 스레드에서 실행합니다.
- 화면에는 직접 즉시 그리지 않고, 이벤트에서 좌표·표시 여부를 저장한 다음 repaint()를 요청합니다.
  paintComponent()는 저장된 상태를 다시 그려 창이 가려져도 그림이 복원됩니다.
- super.paintComponent()로 이전 화면을 지우고 그려 잔상이 남지 않게 합니다.
- 드래그 시 누른 위치의 오프셋을 유지해 이미지가 마우스로 갑자기 튀지 않게 합니다.
- 격자·마름모는 현재 패널 크기로 좌표를 계산해 리사이즈에 대응합니다.
- 파이 차트는 합계 0을 따로 처리하며 누적 비율로 각도를 계산해 마지막 경계가 정확히 360도가 됩니다.
  표시 백분율은 각 항목별 반올림이므로 경우에 따라 합계가 100%에서 조금 달라질 수 있습니다.
- 원문 1-(2)의 설명은 중복된 표현이 있어 실행 그림과 Hide/Show 취지에 맞춰 토글로 구현했습니다.
